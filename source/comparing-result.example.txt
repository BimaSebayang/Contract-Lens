# Contract Comparison Examples

Below are several examples demonstrating how ContractLens detects structural API changes.

---

## Example 1 — No Changes

### Baseline

```json
{
  "name": "Bima",
  "age": 30
}
```

### Current

```json
{
  "name": "Bima",
  "age": 30
}
```

### Comparison Result

```json
{
  "hasChanges": false,
  "breakingChanges": false,
  "risk": "NONE",
  "summary": {
    "added": 0,
    "removed": 0,
    "modified": 0
  },
  "differences": []
}
```

# Risk Levels

ContractLens classifies detected changes into different risk levels.

| Risk | Description |
|-------|-------------|
| NONE | No contract changes detected. |
| LOW | Backward-compatible changes (for example: new optional field). |
| MEDIUM | Changes that may require consumer review. |
| HIGH | Potential breaking changes that can impact existing consumers. |

---

# Supported Change Types

| Change Type | Description | Breaking |
|-------------|-------------|:--------:|
| FIELD_ADDED | A new field is introduced. | ❌ |
| FIELD_REMOVED | An existing field is removed. | ✅ |
| TYPE_CHANGED | Field data type changes. | ✅ |
| REQUIRED_CHANGED *(Planned)* | Optional field becomes required. | ✅ |
